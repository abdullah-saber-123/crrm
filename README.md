# نظام المطابقات والتحصيل وتحليل العملاء

تطبيق Next.js (App Router) + TypeScript + Tailwind، متصل ببيانات Odoo عبر
JSON-RPC، لتحليل التزام العملاء بالسداد، مطابقة الفواتير مع الدفعات، وإدارة
عمليات التحصيل.

## الموديولات

- **لوحة تحليل العملاء** (`/customers`) — داش بورد إجمالي (إجمالي المديونية
  والمتأخر، توزيع المخاطر، رسم بياني مجمّع للمبيعات/التحصيل الشهري، أكثر
  العملاء مديونية متأخرة)، بالإضافة لصفحة تفصيلية لكل عميل
  (`/customers/[id]`) فيها كشف الحساب الكامل، مؤشر الالتزام، أعمار الديون،
  رسم بياني شهري، وتوصيات آلية.
- **المطابقات** (`/reconciliation`) — مطابقة على مستوى **حساب العميل
  بالكامل** (وليس فاتورة بفاتورة): تختار عميلًا وتاريخًا، يحسب النظام رصيد
  الحساب حتى ذاك التاريخ (إجمالي الفواتير − إجمالي التحصيل)، ثم نموذج
  مصادقة (تأكيد/رفض + ملاحظات) يسجّل تاريخ المطابقة ومن صادق عليها، مع سجل
  تاريخي لكل المطابقات.
- **عرض الكولكشن والترشيح** (`/collections`) — موديول قائم بذاته بثلاث
  خطوات: (١) فتح/إنشاء عرض كولكشن، (٢) صفحة "كل العملاء"
  (`/collections/[showId]/customers`) تعرض كل العملاء بأرصدتهم وحدودهم
  الائتمانية لكل الموظفين، وكل موظف يرشّح من يراه مناسبًا بزر ترشيح (يظهر
  للعميل إجمالي عدد مرات ترشيحه)، (٣) صفحة "المرشّحون"
  (`/collections/[showId]/nominees`) تعرض فقط العملاء المرشَّحين مع من
  رشّحهم، وفيها الإدارة تؤكّد تسجيل العميل بالعرض. يتضمن الموديول أيضًا
  جدولة مواعيد الحضور.

## مصادر البيانات

- **Odoo (مصدر الحقيقة المالي)**: `res.partner`, `account.move`,
  `account.payment` عبر `src/lib/odoo.ts`. اضبط في `.env`:

  ```
  ODOO_URL=https://your-company.odoo.com
  ODOO_DB=your-db-name
  ODOO_USERNAME=api-user@example.com
  ODOO_API_KEY=your-odoo-api-key
  ```

  بدون هذه المتغيرات، يعمل التطبيق تلقائيًا على بيانات تجريبية
  (`src/lib/odoo-demo-data.ts`) بنفس شكل بيانات Odoo، حتى يبقى قابلاً
  للتجربة دون اتصال حقيقي.

- **Postgres**: تخزّن حالة الموديولات الخاصة بالتطبيق نفسه (غير موجودة في
  Odoo): سجل مطابقات الحساب، مواعيد الحضور، عروض الكولكشن، الترشيحات،
  والتسجيلات. **مطلوبة دائمًا** (لا يوجد بديل محلي) — اضبط `POSTGRES_URL`
  أو `DATABASE_URL` في `.env`.

  **على Vercel**: مشروعك → تبويب **Storage** → **Create Database** →
  **Postgres** → **Connect** — يضيف المتغير تلقائيًا لإعدادات البيئة.

  **محليًا**: أي قاعدة Postgres (تثبيت محلي، أو قاعدة مجانية من
  [Neon](https://neon.tech) أو [Supabase](https://supabase.com)).

## التشغيل

```bash
npm install
cp .env.example .env   # عدّل بيانات Odoo وPOSTGRES_URL
npm run dev
```

افتح [http://localhost:3000](http://localhost:3000) — سيتم توجيهك لصفحة
تسجيل الدخول (`admin` / `123` كحساب مدير احتياطي دائم من `.env`)
ثم إلى موديول تحليل العملاء.

## المستخدمون والصلاحيات

- المصادقة الآن مبنية على جدول `users` في Postgres، مع كلمات مرور
  مشفّرة (scrypt) وصلاحيتين: **مدير** (يدير المستخدمين ويؤكّد
  المرشّحين) و**موظف** (يرشّح فقط).
- حساب `ADMIN_USERNAME`/`ADMIN_PASSWORD` في `.env` يبقى حساب مدير
  احتياطي دائم (break-glass) يشتغل دائمًا حتى لو قاعدة البيانات فاضية
  أو معطّلة مؤقتًا — لا يمكن حذفه لأنه غير مخزّن بقاعدة البيانات أصلاً.
- المدراء يديرون المستخدمين من صفحة **المستخدمون** (`/users`، تظهر
  بالقائمة الجانبية للمدراء فقط).
- الجلسة نفسها تبقى كوكي موقّع (HMAC) بلا جدول جلسات على الخادم —
  فقط بيانات المستخدم (الاسم/الصلاحية) نفسها انتقلت من متغيرات بيئة
  إلى Postgres.
